# 标准报告模板

按「变化 — 证据 — 含义 — 行动」组织。每节允许为空，空节写明为什么空。

写之前先读快照的 `quality_gates` 与各块 `status`：门槛不允许的结论一律不写。

---

```
## [议题] 政策信号报告

**采集日期：** [date] ｜ **分析截止：** [as_of] ｜ **采集质量：** [complete/partial/failed]
**证据状态：** [evidence_state] ｜ **预测窗口：** 不输出（未标定）

---

### 一、本期最重要的变化及其适用对象

[一段。什么变了、对谁适用。没有变化就写"本期未观察到新增变化"，不凑数。]

**依据：** [来源 + 原句 + 版次/栏目]

---

### 二、与上期对比（七问，逐条回答）

| 问题 | 变了吗 | 旧证据 → 新证据 | 已排除的替代解释 |
|---|---|---|---|
| 措辞变了吗 | | | |
| 范围变了吗 | | | |
| 责任变了吗 | | | |
| 资源变了吗 | | | |
| 程序推进了吗 | | | |
| 执行兑现了吗 | | | |
| 方向分化了吗 | | | |

直接取 `changes.changes`。每条都必须写出**你排除了哪些替代解释**；
排除不掉就写"无法排除"，不要留空。

**可比性：** [changes.status。`not_comparable` 时整表不给结论；
`first_observation` 时只写"本系统首次观察到"，**不得**写"官方首次提出"。]

---

### 三、政策状态（三类分开列，不合并）

**正式措施：** [有文号、发文机关、生效日期的内容。当前来源未接入正式文件库时，
写"本框架尚未接入正式文件来源，本节只能依据公开报道推测，需另行核验"。]

**研究讨论：** [研究、拟、征求意见、学习活动等。]

**执行兑现：** [细则、预算、试点名单、执法信息。未接入则明确写未知。]

---

### 四、企业影响

**暴露关系：** [exposure.relevance —— direct / indirect / unmapped / no_profile]

`unmapped` 表示**关系尚未建立**，不是"与企业无关"：此时本节只写"需补登记暴露环节"，
不做影响推导。`indirect` 时必须先写清楚传导要经过哪几步。

**推导链：** 可核验政策变化 → 企业暴露环节 → 可能影响 → 可逆行动 → 升级触发条件

| 环节 | 本期证据 | 可能影响 | 可逆行动 |
|---|---|---|---|

**必须保留的限定：** [exposure.caveat 原文照抄，不得因为篇幅删掉。]

**尚不能判断：** [明确列出，不要用推测填满。]

---

### 五、替代解释与反证

**当前判断的替代解释：** [至少一条。]

**什么证据会推翻它：** [具体到可检索的对象。]

---

### 六、后续观察

| 看什么 | 在哪看 | 什么条件下升级 |
|---|---|---|
| | | |

原文明确日期（若有）：

| 类型 | 日期 | 原句 |
|---|---|---|
| 生效/截止期限/意见反馈 | | |

没有明确日期时，这一节写"下一项可观察事件"，**不写月份区间**。

---

### 七、数据覆盖与证据索引

- 主题口径：[topic_key] / [topic_version]（口径变更后与旧序列不可比）
- 采集：版面 [fetched]/[expected]，扫描 [total_scanned] 篇，命中 [total_articles] 篇
  （占比 [topic_share]）
- 事件：通过核验 [verified_count] / 未支持 [unsupported_count]，
  证据完整率 [evidence_completeness]，待核验 [needs_review_count]
- 来源：原发 [original_count] 条，转载 [reprint_count] 条，
  跨体系印证 [cross_system_confirmed] 条
- 报道量变化：[coverage_change.signal 或"门槛未通过：原因"]
- 外部媒体：[来源、独立性说明、是否做了时间过滤]
- 本轮未修复项：[known_limitations 中与本报告结论相关的条目]

---

### 附：推荐阅读

| 优先级 | 标题 | 版次 | 栏目 | 为什么值得读 |
|---|---|---|---|---|

按版面权重与目标相关性分别说明，不要用一个总分排序。
```

## 文风

- 执行摘要写段落，不写项目符号。
- 每个结论后接"这意味着……"。
- 不确定时写"倾向于判断……，证据有限"，不写绝对话。
- 去掉"综合来看""如上所述"。
- 读者是企业管理层：不出现"管道""字段""JSON""权重"这类技术词。
- 不使用"基本完成"这类无法核验的表述。
