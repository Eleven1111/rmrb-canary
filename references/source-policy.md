# 来源角色与采集质量

## 来源分层

| 来源层 | 回答的问题 | 当前状态 |
|---|---|---|
| 正式政策原文（国务院） | 谁正式规定了什么、对谁适用、何时生效 | **已接入**，覆盖有限，见下 |
| 正式政策原文（部委、地方主管部门） | 同上 | **取不到**，见下方实测表 |
| 会议通稿、公开征求意见、政策解读 | 议题进入哪个公开程序，哪些条款未定稿 | 尚未接入，P1 第一批 |
| 人民日报 | 议程如何突出、政策如何被解释和传播 | **已接入**，主轴 |
| 人民网 RSS | 同体系报道的补充 | 已接入，见下方独立性说明 |
| 微博/百度热搜 | 议题是否进入大众视野 | 已接入，采样不稳定 |
| 实施与执行证据（细则、预算、试点名单、执法信息） | 是否落地、在哪些地区落地 | 尚未接入，P2 |
| 企业公告、统计数据 | 现实影响与预期差 | 未接入，可选 |

## 正式文件来源：实测状态（2026-09-08）

| 来源 | 状态 | 实测结果 |
|---|---|---|
| 中国政府网 `/zhengce/` | **可用** | 首页约 6 件国务院层级文件；详情页可取发文机关、发文字号、成文日期、发布日期、索引号、正文 |
| 中国政府网 `/zhengce/xxgk/` | **可用** | 信息公开专栏，更新慢，主要作解析器回归样本 |
| 政策文件库分页 `/zhengce/zhengceku/` | 取不到 | HTTP 403 |
| 国务院政策文件库检索接口 | 取不到 | HTTP 200 但 `data=null`；浏览器打开页面同样为空 |
| 国家互联网信息办公室 | 取不到 | HTTP 521 —— **AI 主题最关键的主管部门缺口** |
| 国家卫生健康委 / 国家药监局 | 取不到 | HTTP 412 —— 疫苗主题主管部门缺口 |
| 工信部 / 发改委 / 疾控局 | 未实现 | 首页可达但栏目页为空壳或链接由 JS 注入 |

完整登记在 `config/sources/policy_sources.json`。**取不到的来源留在配置里并标注探测结果，
不删掉假装不存在** —— 覆盖缺口本身就是必须呈现的信息。

### 由此产生的硬约束

- 已接入来源只有国务院层级最近若干件文件，**不是完整政策语料库**。
- 因此"未检索到相关文件"只能写成"**已接入来源中没有**"，
  绝不能写成"没有出台文件"。程序层面：`quality_gates.official_document_claims_allowed`
  只有真的取到文件时才为真。
- 发现延迟偏大是结构性的：只轮询首页最新几件，早于此的文件要等到它出现在首页才会被看到。
  实测两个试点主题的发现延迟中位数约 57 天，这是覆盖方式决定的，不是偶然。

## 正式文件 vs 报道

两者证据力不同，`signals.by_source_layer` 分开计数，绝不合并：

- **正式文件**回答"正式规定了什么"。事件带文号、发文机关、发布/生效日期。
  文件正文大量使用无主语句（"深入实施……行动"），其主体取发文机关 ——
  这是文件自带的元数据，不是推断，但仍标 `subject_source='document_metadata'` 并待核验。
- **人民日报报道**回答"议程如何呈现"。不能用报道断言正式规定的内容。

## 独立性

- 人民网与人民日报同属人民日报社体系，**不是独立信源**。
  两者同时出现不构成交叉验证，只是同一体系内的传播强度。
- 转载数量属于传播强度，不能当作多个独立决策证据。
- 热搜榜受平台机制与采样时点影响，缺席不等于无关注。

## 共享文档缓存（P2）

多个主题分析同一期时，**只抓一次**。缓存的是整期全文，关键词过滤在本地做，
因此"同一期"对不同主题就是同一份证据，而不是两次抓取的两个快照。

- 内容哈希变化 → **新增版本**而非覆盖，修订因此可被检出。
- `first_seen_at` 与 `published_at` 严格分开：今天补采一份旧文件，
  不等于系统当年就发现了它。
- 实测：两个主题冷启动 120s+/个，热缓存后整批 9.2s，命中率 1.0。

## 已知采集缺陷（F07，P1 修复项）

`media_fetch` **没有按时间范围过滤**。输出里的"近 N 天"不成立，
`time_filter_applied: false` 明确标出了这一点。引用外部条目时必须自行核对 `pub_time`。

## 采集质量状态

`fetch_quality.status`：

| 状态 | 含义 | 允许写什么 |
|---|---|---|
| `complete` | 版面目录可用，全部版面与文章采集成功 | 全部结论，包括"完整采集后零命中" |
| `partial` | 有版面或文章失败，或文章覆盖率 < 98% | 只写已获得的证据；**禁止**任何"沉默/降温/消失"结论 |
| `failed` | 版面目录不可用 | 只写采集失败本身 |

字段：`expected_pages` / `fetched_pages` / `failed_pages` / `expected_articles` /
`total_scanned_articles` / `failed_articles` / `article_coverage`。

**采集异常进运维提醒，不进政策判断。** 来源坏了就是来源坏了，不是官方不提了。

## 报道量变化的数据门槛（§7.3）

`coverage_change` 只在同时满足下列条件时才给结论，否则返回 `gate_blocked`：

1. 本期 `fetch_quality.status == complete`；
2. 同 topic_id、同算法版本、且**采集完整**的历史观测 ≥ 5 期；
3. 历史记录严格早于 `as_of`；
4. 同一日重复运行只算一条样本（存储层幂等键保证）。

通过门槛后，先比"主题占全部有效报道的比例"，再看原始篇数。
输出词只有：本期零命中 / 报道减少 / 报道增加 / 波动在历史范围内。
**不输出**"风险解除""刻意回避""官方冷处理"。
